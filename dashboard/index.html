Case Study 1: The $39.4k Date-Boundary Materialized View Anomaly (Q1)

When calculating a rolling 1-month revenue metric (e.g. order_ts >= now() - INTERVAL '1 month'), the cutoff timestamp falls mid-day. A naive Materialized View aggregated daily from midnight overcounts prior morning hours.

Midnight 00:00 to Cutoff 14:30 ❌ Naive MV Overcounts: +$39,475.01
Cutoff 14:30 to 23:59 (Raw Delta) ⚡ Queried from Raw Tables
Closed Full Days (Day 2 to Day 30) ✅ Queried from Fast MV (0.05ms)
The Boundary-Safe Hybrid Query Architecture (queries/q01/materialized_view_boundary_safe_plan.sql) 
WITH p AS MATERIALIZED (
  SELECT now() - INTERVAL '1 month' AS cutoff
)
SELECT SUM(amount) AS monthly_revenue
FROM (
  -- 1. Full enclosed historical days from MV (Lightning Fast)
  SELECT m.gmv AS amount
  FROM ecom.mv_daily_gmv m CROSS JOIN p
  WHERE m.day > date_trunc('day', p.cutoff)
  
  UNION ALL
  
  -- 2. Real-time fractional boundary delta from raw indexed tables (Zero Overcount)
  SELECT oi.line_total
  FROM ecom.orders o
  JOIN ecom.order_items oi ON oi.order_id = o.order_id
  CROSS JOIN p
  WHERE o.order_status IN ('paid', 'shipped', 'delivered')
    AND o.order_ts >= p.cutoff
    AND o.order_ts < date_trunc('day', p.cutoff) + INTERVAL '1 day'
) s;
Direct Raw Query: $1,422,428.75
Naive MV: $1,461,903.76 (+$39.4k Error)
Boundary-Safe Hybrid MV: $1,422,428.75 (0.00 Parity)

Case Study 2: Eliminating Correlated EXISTS Loop (Q6)

Calculating 30-day repeat purchase cohorts. The baseline executed a correlated subquery 2,222 times causing 5,633 buffer page hits. Replacing it with a pre-aggregated CTE reduced buffer I/O to 142 pages in a single table pass.

❌ Baseline Correlated SubPlan

-> Seq Scan on orders (cost=0..504 rows=2222)
   SubPlan 1
     -> Index Scan on orders (loops=2222)

✅ Tuned Hash Left Join + CTE

-> Hash Left Join (cost=142..280 rows=2222)
   -> CTE Scan on first_orders (1 pass)
